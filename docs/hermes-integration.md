# Optional Hermes integration

ThesisLens works without Hermes, X/Twitter, a hosted model, or notification credentials. Hermes can consume ThesisLens's bounded REST API and should not access the SQLite database or compute its own 13F differences. The included [`integrations/hermes/SKILL.md`](../integrations/hermes/SKILL.md) follows Hermes's current skill format; copy that folder into the profile's skill directory or configure an external skill directory as described in the [official Hermes skills guide](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md). This integration was not tested against a running Hermes installation.

Run FastAPI on `127.0.0.1:8000` only. The API is single-user and unauthenticated; do not expose it to a public interface, reverse proxy, or messaging bot without independently adding authentication, authorization, TLS, and rate limits. Hermes may use its own optional local model endpoint; a paid model subscription is not required by ThesisLens. If Hermes runs elsewhere, use a trusted private tunnel with those controls rather than making this API public.

Read-only endpoints: `GET /api/intelligence/feed` (filters: `all`, `investors`, `institutions`, `companies`, `insiders`, `public_updates`, `my_watchlist`), `GET /api/intelligence/company/{ticker}`, `GET /api/intelligence/daily-brief`, `GET /api/investors/{id}`, `GET /api/company/{ticker}`, and existing Ask endpoints. `PUT /api/intelligence/events/{id}/read` mutates only local read state; ask before using it. Each feed item includes its original URL and dated reporting/publication context.

Notifications default to local outbox only. `python -m backend.refresh --notification-dry-run` previews the exact eligible Telegram, ntfy, and Hermes-consumer messages without credentials, network calls, or state changes. Hermes remains a REST consumer, not an outbound delivery provider. To opt into free delivery, set `THESISLENS_NOTIFICATION_CHANNEL=telegram` with `THESISLENS_TELEGRAM_BOT_TOKEN` and `THESISLENS_TELEGRAM_CHAT_ID`, or `THESISLENS_NOTIFICATION_CHANNEL=ntfy` with `THESISLENS_NTFY_BASE_URL` (default `http://127.0.0.1:2586`) and `THESISLENS_NTFY_TOPIC`. Run `python -m backend.refresh --notifications` from the project's `.venv` on an explicit schedule. One invocation sends at most one item; quiet hours (UTC 22:00–07:00 by default), a daily cap (20 by default), deduplication, and a 15-minute retry delay apply. Failed sends preserve the local event. Digest-only events remain in the daily brief rather than the immediate outbox. There is no paid broadcast mode or Twilio integration. Telegram's [ordinary Bot API limits](https://core.telegram.org/bots/faq) still apply; self-hosting ntfy is documented in its [official terms](https://docs.ntfy.sh/terms/).

The default scheduler/CLI does not crawl all managers or fetch investor letters. Use `--public-updates` for due official RSS sources and `--intelligence` to materialize events from last-good caches. Source publication dates, not ingestion time, govern the daily brief. Empty sections mean no matching cached dated event, not no real-world activity.
